# صفحهٔ وب پروکسی‌ها

هر ۱۰ دقیقه (طبق برنامهٔ GitHub Actions، با احتمال تأخیر در اجرا) پروکسی‌های MTProto از منابع `sources.txt` جمع می‌شوند، هرکدام با handshake واقعی MTProto تست می‌شوند (پروکسی باید درخواست را واقعاً به سرور تلگرام برساند و جواب درست برگرداند؛ همان تستی که خود اپ انجام می‌دهد)، بر اساس پایداری و پینگ مرتب می‌شوند و در یک صفحهٔ ساده منتشر می‌شوند. روی هر پروکسی که بزنید، تلگرام باز می‌شود.

| فایل | کار |
|---|---|
| `web/build_site.py` | جمع‌آوری، تست و ساخت سایت (پایتون ۳ + `cryptography`) |
| `web/mtproto_check.py` | تست واقعی MTProto (برگردان‌شده از HealthChecker خود اپ) |
| `web/index.html` | خود صفحه (فارسی، موبایل‌پسند، دکمهٔ «تست از دستگاه من») |
| `web/sources.txt` | منابع پروکسی؛ هر خط یک آدرس. هر وقت خواستید اضافه یا کم کنید |
| `.github/workflows/proxy-site.yml` | اجرای خودکار روی گیت‌هاب و انتشار در GitHub Pages |

## امنیت

- محتوای پیام‌ها و فایل‌ها را خود تلگرام (MTProto) رمز می‌کند. هیچ پروکسی‌ای نمی‌تواند آن را بخواند یا تغییر دهد.
- چیزی که هر پروکسی می‌بیند: آی‌پی کاربر، زمان اتصال و حجم داده.
- برای همین `build_site.py` سرورهایی را که آی‌پی‌شان در محدوده‌های ثبت‌شدهٔ ایران است حذف می‌کند (لیست از [ipverse/rir-ip](https://github.com/ipverse/rir-ip)). آدرس‌های خصوصی و آدرس‌هایی که resolve نمی‌شوند هم حذف می‌شوند. اگر لیست آی‌پی‌های ایران دانلود نشود، صفحه به‌روز نمی‌شود و نسخهٔ قبلی می‌ماند.
- هر ✗ که کاربر می‌زند فقط روی همان دستگاه ذخیره می‌شود. آن پروکسی و پروکسی‌های هم‌گروهش (همان دامنه یا همان شبکهٔ /24) پایین می‌روند.

## روش ۱: GitHub Pages (رایگان، بدون سرور)

1. این فایل‌ها را در شاخهٔ `main` قرار دهید (push کنید).
2. در ریپو: **Settings ← Pages ← Build and deployment ← Source** را روی **GitHub Actions** بگذارید.
3. در تب **Actions** گزینهٔ «Proxy web page» را باز کنید و **Run workflow** را بزنید.
4. چند دقیقه بعد صفحه اینجاست: `https://mohammadrezasmz2.github.io/AutoConnector_for_Telegram/`

بعد از آن هر ۱۰ دقیقه برای به‌روزرسانی تلاش می‌شود. صفحهٔ باز کاربر هر ۶۰ ثانیه فایل فهرست را دوباره می‌خواند و در هر دقیقه، ۱۲ پروکسی بالای لیست و حداکثر ۴۸ پروکسی چرخشی را با روش تقریبی مرورگری پایش می‌کند. این روش با تست واقعی MTProto متفاوت است. اگر تب در پس‌زمینه باشد پایش مرورگر متوقف می‌شود و هنگام بازگشت ادامه پیدا می‌کند.

در سربرگ سایت فقط دکمهٔ 🛡 برای باز کردن توضیحات امنیت در پنجرهٔ جدا (بدون اشغال فضای بالای اتصال) دیده می‌شود. منوی تم دارای سه انتخاب **مشکی (پیش‌فرض برای کاربران جدید)**، **ماتریکسی مشکی‌ـ‌سبز** و **سفید** است؛ انتخاب کاربر در مرورگر ذخیره می‌شود. دکمهٔ «اتصال به بهترین پروکسی» همیشه با پس‌زمینهٔ سفید و نوشتهٔ مشکی نمایش داده می‌شود. قسمت «لاگ اتصال پروکسی‌ها» جدا از لاگ فنی، بازشدن لینک، نتیجهٔ اعلامی کاربر، دریافت فهرست جدید و خلاصهٔ تست‌های دوره‌ای را نشان می‌دهد. نمودار پینگ از زمان بازشدن صفحه فعال است. اگر پروکسی جدیدی امتیاز بهتری داشته باشد، دکمهٔ امتحان آن نشان داده می‌شود؛ **مرورگر نمی‌تواند پروکسی فعال داخل تلگرام را بدون اقدام کاربر تغییر دهد.** (گیت‌هاب اجرای زمان‌بندی‌شده را گاهی چند دقیقه دیر می‌اندازد. اگر ریپو ۶۰ روز هیچ commitی نداشته باشد، اجرای خودکار را متوقف می‌کند. در آن صورت از تب Actions دوباره فعالش کنید.)

## روش ۲: سرور یا هاست خودتان

روی هر سروری که پایتون ۳ دارد (VPS یا هاست سی‌پنل با Python):

```bash
git clone https://github.com/mohammadrezasmz2/AutoConnector_for_Telegram.git ~/autoconnector
pip3 install cryptography
python3 ~/autoconnector/web/build_site.py --out /var/www/html/proxy     # یک بار برای تست
```

سپس با `crontab -e` (یا بخش Cron Jobs در سی‌پنل) این خط را اضافه کنید:

```
*/10 * * * * cd ~/autoconnector && git pull -q; python3 web/build_site.py --out /var/www/html/proxy >> ~/proxy-site.log 2>&1
```

در سی‌پنل مسیر خروجی معمولاً این است: `--out ~/public_html/proxy`. صفحه در `https://دامنه-شما/proxy/` باز می‌شود.

> سرور باید به اینترنت آزاد دسترسی داشته باشد (سرور خارج از ایران). سرور داخل ایران نمی‌تواند منابع را دانلود کند.

## تنظیمات

`--top 300` تعداد پروکسی‌های نمایش‌داده‌شده · `--rounds 3` تعداد دفعات تست هر پروکسی · `--timeout 6` حداکثر ثانیه برای هر اتصال · `--concurrency 300` تعداد تست‌های هم‌زمان

## محدودیت‌ها

- پینگ «سرور» از جای سرور (مثلاً آمریکا یا اروپا) اندازه گرفته می‌شود، نه از ایران. پروکسی‌ای که آنجا سریع است شاید در ایران فیلتر باشد. برای همین دکمهٔ **تست از دستگاه من** هست: ۶۰ پروکسی اول را از شبکهٔ خود شما تست می‌کند و دوباره مرتب می‌کند.
- این تست مرورگری تقریبی است، چون مرورگر نمی‌تواند handshake واقعی MTProto بزند و خطاهای HTTPS/CORS اثبات قطع بودن پروکسی نیستند. تست واقعی در GitHub Actions هنگام ساخت فهرست انجام می‌شود. اتصال خودکار و جابه‌جایی واقعی پروکسی فقط در خود اپ AutoConnector (یا سرویس سمت دستگاه/سرور) ممکن است.
- GitHub Actions اجرای دقیق هر ۱۰ دقیقه را تضمین نمی‌کند و در ساعات شلوغ ممکن است با تأخیر اجرا شود. برای تست واقعی هر پروکسی در هر دقیقه به یک سرویس مانیتورینگ دائمی نیاز دارید.
- لینک‌ها `tg://` هستند، نه `t.me`، چون `t.me` در ایران فیلتر است.

## نحوهٔ رتبه‌بندی و اعتبار لاگ

- در زمان ساخت هر فهرست (هدف: هر ۱۰ دقیقه) **تمام پروکسی‌های جمع‌آوری‌شده** با درخواست واقعی MTProto و پاسخ `resPQ` بررسی می‌شوند؛ پروکسی‌های بدون پاسخ وارد فهرست برتر نمی‌شوند. پروکسی‌ها با ترکیبی از میانهٔ تأخیر، نرخ پاسخ و ترجیح محدود FakeTLS مرتب می‌شوند.
- هر ۶۰ ثانیه، تا ۶۰ پروکسی از فهرست (پروکسی‌های بالای لیست + نمونه‌های چرخشی) در مرورگر با آزمون تقریبی HTTPS سنجیده می‌شوند. پاسخ مثبت می‌تواند به رتبه‌بندی کمکی کمک کند، اما خطای CORS/TLS یا عدم پاسخ HTTPS، شاهد قطعی شکست MTProto نیست.
- صفحهٔ باز فایل `proxies.json` را هر دقیقه دوباره دریافت می‌کند تا پس از انتشار فهرست جدید فوراً رتبه‌بندی تازه نشان داده شود. **اجرای دقیق هر ۱۰ دقیقه توسط GitHub Actions تضمین نیست**؛ برای آزمون واقعی تمام پروکسی‌ها هر دقیقه باید یک سرویس دائمی جداگانه مستقر شود.
- لاگ اتصال فقط آنچه سایت دیده، تست سرور منتشر کرده یا کاربر تأیید کرده است نمایش می‌دهد؛ سایت به وضعیت داخلی اتصال پروکسی در اپ تلگرام دسترسی ندارد و نمی‌تواند پروکسی فعال داخل تلگرام را خودکار تعویض کند.

## بهبود شناسایی بهترین پروکسی (نسخهٔ جدید)

- پروکسی‌ای که در دور اول تست MTProto جواب نمی‌دهد، **یک فرصت دوباره** دریافت می‌کند تا خطاهای لحظه‌ای باعث حذف آن نشود؛ پروکسی‌های تأییدشده با چند تلاش واقعی دوباره بررسی می‌شوند.
- معیار رتبه‌بندی شامل **میانهٔ زمان handshake واقعی MTProto**، **نرخ پاسخ موفق**، **نوسان تأخیر / jitter**، **کندترین نمونهٔ ثبت‌شده** و سابقهٔ اندازه‌گیری‌های نوبت‌های قبلی است. سابقه با GitHub Actions Cache بین اجراها منتقل می‌شود؛ تا اولین اجرا و چند نوبت بعد، سوابق هنوز محدود خواهند بود.
- رتبهٔ پروکسی‌ها دیگر از زمان پاسخ HTTPS مرورگر محاسبه نمی‌شود. این تست مرورگری نه سرعت انتقال فایل در تلگرام را اندازه می‌گیرد، نه عملکرد واقعی MTProto را اثبات می‌کند. دکمهٔ بررسی HTTPS فقط برای عیب‌یابی تقریبی باقی مانده است.
- گزارش «در تلگرام وصل شد/نشد» فقط برای همان مرورگر ذخیره می‌شود و برای **۱۲ ساعت** در اولویت‌بندی اثر دارد؛ نتیجه‌های قدیمی خودبه‌خود از اثرگذاری در رتبه‌بندی خارج می‌شوند. سایت بدون مجوز کاربر وضعیت واقعی داخل اپ تلگرام را نمی‌بیند.
- پینگ MTProto ارائه‌شده **از شبکهٔ ماشین اجرای GitHub Actions** است و با پینگ و سرعت دانلود واقعی از ایران یا شبکهٔ هر بازدیدکننده متفاوت است؛ برای انتخاب قطعیِ سریع‌ترین پروکسی برای یک شبکهٔ خاص، تست داخل اپ تلگرام/AutoConnector روی همان شبکه لازم است.
